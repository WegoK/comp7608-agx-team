# FPS 第四版候选：Mirage 跳跃无水平进展保护

2026-11-25（北京时间）。用户要求直接修改并再出上传包。在长期分支 `codex/haoran-fps` 上，以第三版源码 `65652c51f1ef60fb1f365b45bfff3eaa947c7f40`、包 `67e64a8436fe…` 为固定对照，修复 [da9ec3c5 复盘](../R02-haoran-fps-da9ec3c5/README.md) 中原地上下跳、恢复被反复重置的问题。“第四版”为开发候选名，尚无平台v4序号回执。

## 本轮改动

- 仅Mirage导航恢复使用**水平距离**衡量向当前路点的进展；跳起来造成的Z距离缩短，不再清除无进展窗口和跳跃失败状态。
- Mirage同一路点每次跳跃尝试后保留900 ticks（15秒）冷却；窗口重置、短暂进展或回调中断不清除此冷却，换回合/地图/导航任务按原导航生命周期重置。
- Mirage的后退/侧移卡住检测也使用水平位置；垂直起伏不再掩盖原地卡住。重接导航图或完成后退侧移后的绕路，均等落地后进行，避免用半空位置选择楼层。
- **到达路点和终点仍使用3D距离**。正常有水平进展的台阶/坡道用例、落地和正常前进用例保持；不能在楼下因XY重合就认为已到楼上。
- 第三版可见交战、18-tick瞄准记忆、下包/拆包、搜点顺序和购买代码未改。`starter_player.py`与第三版一致；`Candidate`源码只有`navigate`方法改变。另四地图保留原3D恢复规则。Racing不改。

失败入口在A*中间节点的重复选择问题**没有在本轮一起修改**，因此不能声称本包解决全部Mirage绕圈。先验证跳跃恢复这一项，再单独处理黑名单路径搜索。

历史复算仍沿用旧版位置、视野和对手动作。**49→4是跳跃请求变化，不代表新策略已实际脱困、到达A或拆包成功。** 15秒冷却可能延迟对同一路点的有效再次尝试；水平进展判断在特殊垂直移动场景也需实战验证。本轮检查不能代替游戏环境测试。
