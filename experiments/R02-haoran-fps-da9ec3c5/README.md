以下均为1起始回合号（JSON为0起始）。第 **1、7、9、11回合**均进攻超时失败、没有交战开火。对同一批第三版实际观察，v2/v3在这四回合的动作**完全一致**，因此这些轨迹不是本次瞄准保持新增的动作差异。

第1回合最后60秒，实际水平路程144.22m，但XY始终位于约 **3.38×2.09m** 的小区域。这里是来回移动，不是绝对静止；旧审计的“十秒后回到近点”窗口会重叠，不能把这些窗口条数加起来当卡住秒数。本次单独记录了末60秒位置范围和实际轨迹。

源码原因：Mirage未开启 `long_avoid`；`_failed_anchors` 虽然记录了900-tick冷却，但默认主要用于挑重接起点，A*中间节点只有 `long_avoid=True` 时才跳过黑名单。于是新路线仍可能绕回这个失败点。上述仍在冷却内再次恢复的计数来自冻结策略内部状态，不是仅凭动画猜测。

**独立候选方向**：Mirage恢复路径时让未过期失败连接/入口真正参与路径搜索，避免从另一个起点又回到同一坏点；保持同层重接、路径存在性和冷却到期恢复。不直接复制Dust2全部参数，也不把不同楼层的所有相近节点永久封死。

## 主问题二：跳跃被当成了前进

第 **14回合**本人请求跳跃 **49次**，主要反复朝高约1.1m的同一路点尝试，恢复重规划仅2次。最后60秒XY位置几乎固定在 **(91.88837,51.19054)**，但Z不断变化。审计在排除初始2秒观察窗口后，测到 **72.6秒**连续“发出移动指令、2秒内所有XY样本仍在0.2m内”。

炸弹引信的800次观察（40秒）本人全程存活，包位始终未知，没有拆包请求；距B中心最近15.57m，公开回放证实实际包在A。

导航当前使用到路点的3D距离判断进展，跳起来会短暂接近较高路点，从而重置进展窗口并重置 `_jump_tried`。另一层卡住检测也看3D位置变化，因此上下跳能阻止后退侧移恢复。连续跳跃样本中 `escape=None`，同一路点反复被允许跳跃。这解释了“角色看起来一直在动，水平却没前进”。

**建议下一版优先做这个最小修复**：水平没有进展时，不让纯Z方向起伏反复清除失败状态；同一目标的跳跃尝试次数/冷却独立于短暂3D距离变小。有限次失败后切换后退侧移和绕路。要保留正常台阶、落地、坡道、楼梯与交战/拆包优先级，不能把所有高度变化都当作卡住。

该第14回合v2/v3动作也完全一致，不建议因为这一局回退第三版的瞄准保持。
