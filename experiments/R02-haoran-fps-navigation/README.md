## 问题、假设与实现

R08 的 `_detour` 对全部导航节点按距离排序，再从中选择最近的合格挂接点。实际只使用排序后的一个节点，可用一次扫描同时选出全局最近节点和合格最近节点，去掉全图排序的时间与列表分配。

实现保留高度与半径边界、失败节点/边的有效期、当前受阻目标的排除、目标节点选择及后续 A*。距离相等时只用严格小于更新，保留原始节点插入顺序，与 Python 稳定排序的选择一致。

最初曾以课件 starter 尝试坡面容差和持续脱困；读取最新交接说明与小组现有实验后，未采用这份草稿，改为在 R08 上做本次局部优化。先前草稿的 14 组程序检查与 5,000 次调用不计作本候选证据。没有复制整份工具包策略覆盖 R08。

- 2,400 次合成观测调用：恢复、交战/拆包中断、回合切换等情况下，动作与 R08 完全一致；检查所发数值动作的有限性与范围。这不是完整平台准入验证。

## 局部耗时观察

使用工具包全部三维候选点，刻意设置空邻接，隔离节点筛选开销。它们不是实战导航图；不存在整局模拟、真实路线长度或胜率。每图原版和候选各 7 批，每批 20 次，交替执行顺序，表中为每次调用墙钟耗时的批次中位数。数字只适用于这次本机测量，不代表平台 CPU 预算验证。

| 地图 | R08（ms） | 候选（ms） | 变化 |
|---|---:|---:|---:|
| Borgo | 15.054 | 10.048 | -33.26% |
| Dust2 | 11.224 | 8.892 | -20.78% |

| Nevaio | 18.621 | 12.598 | -32.34% |

这里的收益只属于 `_detour` 中节点筛选的构造测试。真实 `_detour` 还要执行路径搜索；总 CPU、内存、故障率、任务到达率和比赛表现均尚未测得。
