初次准备：2026-11-20（北京时间）。截至 2026-11-21，用户确认此包已用于平台运行并提供累计成绩截图；逐局冻结版本和准入/激活回执待补。

- 对照基线：`4555a0a57521ffdc998992c93b6d7e567ebe3e74`，即小组 R08 加此前的节点筛选效率优化。
- 候选代码与包：以 [package-manifest.json](package-manifest.json) 的 `git_sha`、`zip_sha256` 追溯；后续报告提交可不同。
- 用户指出前一次工作没有改比赛决策。本实验单独增加目标策略，不将先前的耗时下降写成战术或胜率提升。

## 问题与假设

源码检查发现，R08 的 `Player.act` 会按席位和回合指定 A/B 包点，处理安放后炸弹，却没有掉落炸弹的回收分支。合成场景也重现了这一点。没有本人实战日志，因此这里是源码问题与策略假设，不是已观测到的某场失败结论。

假设：进攻方在炸弹掉落、位置合法可知且当前没有优先交战时，先导航到炸弹，而不是继续去原定包点，可以增加回收炸弹、继续安放的机会。实际收益仍需比赛验证。

## 实现与决策优先级

只在 `strategies/fps/agent.py` 新增 `dropped_bomb_goal`，并在 `Candidate.move` 中使用该目标。满足进攻方、本人未携包、状态为 `world`、位置为三个有限数时，目的地改为炸弹位置。位置未知或无效时继续既有决策。

导航到达后，实际自动拾取由平台对距离和可见性裁定；本策略不制造拾取成功状态。下一次观察若确认本人携包，目标恢复原来的 A/B 包点。可见敌人交战、安放和拆除仍由既有 `Player.act` 优先处理。

曾考虑通过携包者席位预测共同进攻点，但五人可能使用不同策略，席位不能确定其意图，本次未采用。也没有将工具包的二维候选网格替换成实际导航图。
